### handoff-tests-and-startup-sweeps
**Status**: completed
**Started**: 2026-11-16
**Landed**: 2026-11-16

#### Changes Made
- `src/proxy/mcp-proxy.ts`: the env file's name shape is one constant (`ENV_FILE_NAME`) and one function (`newEnvFileName`) used by `dockerConnector` and by the new exported `sweepEnvFiles(cfg, now = Date.now(), log = noop): number`. It lists `<dataDir>/tmp` (missing: return 0; any other failure: log the directory and the message, return 0), and for each name matching `^env-[0-9a-f]{16}$` does `lstatSync`, requires a regular file older than `max(3600, 2 * cfg.mcpStartupTimeoutSec)` seconds, and `unlinkSync`. A failure on one file is logged by name and the loop goes on; `ENOENT` is ignored. It never reads a file and never creates `tmp`. `dockerConnector`'s behavior is unchanged.
- `src/registry.ts`: `Registry.sweepTemps(now = Date.now(), log = noop): number`, same shape, for `^registry\.json\.\d+\.tmp$` older than the constant `TEMP_MAX_AGE_MS` (one hour), in the registry's directory. No lock, no `refresh`, no `persist`; the comment says why and what it does not cover.
- `src/server.ts`: `App.reconciling` is renamed `startup`. On the first `start()` only (guard: `!this.startup`, field assigned in the same synchronous block), the env-file sweep and the registry temp sweep run synchronously, each in its own `try` through a private `sweep(kind, run)`, then the reconciliation starts and its promise (never rejecting) is the field. A sweep that removed something logs `startup: removed N leftover env file(s)` or `... registry temp file(s)`; nothing is logged for zero; a throw logs `startup: <kind> sweep failed: <message>`. The registry refresh before them keeps its own `try`, so a corrupt registry file does not stop the sweeps. `shutdown()` and `stop()` do not wait for the field.
- `README.md`: one parenthetical at the private-temporary-file passage.
- Tests: `test/proxy.test.ts` (directory mode and client environment; a value with a line break throws and leaves no file; two cases taking a real env file through `McpProxy`, success and failed handshake; `describe("sweepEnvFiles")`, 15 cases); `test/registry.test.ts` (`describe("Registry.sweepTemps")`, 10 cases); `test/server.test.ts` (field renamed in the three flight 02 cases and the `afterEach`; the comment above the `Docker.exec` assertion; `describe("sweeps")`, 6 cases).

### registry-version-check
**Status**: completed
**Started**: 2026-11-16
**Landed**: 2026-11-16

#### Changes Made
- `src/registry.ts`: one constant, `REGISTRY_VERSION = 1`, used by `RegistryFile.version`, by the check and by `persist()`. In `refresh()` the parse and the read of `version` (as `unknown`) stay in the `try` (a `null` top level still throws there and is reported as unreadable); the check follows it, before `this.projects` is assigned and before `this.mtimeMs` is set. Order: `undefined` continues; equal to the constant continues; an integer number greater than the constant throws the newer-version error; anything else throws `Registry file <path> is unreadable: unsupported version <JSON.stringify(version)>`. Every write forces a `refresh()` under the lock first, so the check also guards `put`, `delete` and `update`.
- Newer-version message: `Registry file <path> was written by a newer version of mcp-everything (format N; this build reads format 1). The file is left untouched. Upgrade mcp-everything. Moving the file aside starts this build with an empty registry, but the sandboxes of the projects in it stay in Docker and are no longer listed.`
- `README.md`: one sentence in the `MCPE_DATA_DIR` row.
- `.github/workflows/ci.yml`: floor 430 to 480; comment "447" to "500". Nothing else.
- Tests: `test/registry.test.ts` (`describe("a registry file with a version")`, 17 cases: newer refused with message, never rewritten by `put`/`delete`/`update` with bytes, temp and lock checks, refused again then accepted, in-memory records kept, missing version, `1.0`, eleven unsupported values); `test/server.test.ts` (one case in `describe("sweeps")`: newer file at startup, startup resolves, both sweeps ran, `registry:` and `reconcile:` log lines, `list_projects` error, bytes unchanged).

#### Verification
- Reproduction, cases written first and run against the unchanged `refresh()`: 16 of the new cases failed. For a file `{"version":2,"projects":{"x":...},"future":true}` the unchanged code loaded it (`refresh()` returned true, `list()` held `x`; no throw), and after one `put` of a second record the file held `version: 1`, keys `version,projects` only (the `future` key gone, version rewritten to 1), projects `x,y`. That is the downgrade data-loss path: a newer file is silently rewritten in the older format.
- After the change: `npm run typecheck` clean; `npx vitest run --testTimeout 20000`: 500 passed, 18 skipped (before: 482 passed, 18 skipped).
- Floor: the multiple of 10 between 15 and 24 below 500 is 480. The workflow's count step, run locally with `RUNNER_TEMP` in a scratch directory: `500 tests passed (floor 480)`. The workflow parses as YAML.
- By reading: the check precedes the assignment of `this.projects` and the update of `this.mtimeMs`, so a refused file is read again on every call.
- The Docker suite was not run; no squawk 0034 behavior is pinned by any test.

#### Notes
- A top-level array, number or string still loads as an empty registry (squawk 0034, untouched).
- An install already running when a newer file appears will fail its next `put`; accepted with the flight's trade-off, not tested.

#### Review fixes
The assertion `toThrow(expect.not.stringMatching(/unreadable/))` was vacuous: vitest passes the Error object to the matcher, so `stringMatching` never matched and the `not` always passed. The `.*` in the other newer-version patterns also let a rewrapped "is unreadable: Registry file ... was written by a newer version" message through. A `thrown()` helper now returns the message, and every newer-version assertion in `test/registry.test.ts` matches an anchored pattern with `\S+` for the path (it cannot span the space in a rewrap) and, in the main case and the put/delete/update case, also asserts the message does not match `/unreadable/`. The server test anchors the tool result and both log lines the same way. Proof: with the version check moved inside the `try`, so the `catch` rewraps it, 5 cases failed (the four registry cases that assert a newer version, and the server startup case), each on the anchored match; after undoing the move, `Registry.refresh()` was identical to before (diffed) and both files passed. Also: the temp-file name now comes from one `tempName`/`isTempName` definition shared by `persist()` and the sweep, and an `Infinity` version reads `unsupported version Infinity` (the test writes the message as a literal).
